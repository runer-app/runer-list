# runer-list

One repo: `app/` (Tauri client: TypeScript, Svelte, Rust), `server/` (Go + PostgreSQL), `protocol/` (the protocol
docs and the conformance data both sides test against). Each side has its own Makefile and README; the root
Makefile delegates to them. The protocol rules are only in `protocol/docs/`; `docs/` covers the
app (`app.md`), self-hosting and releasing, and links to the protocol instead of restating it. The server's layout is in
`server/README.md`.

## Protocol data

`protocol/vectors` (crypto, generated by `app/crates/runer-crypto`'s `generate` test) and `protocol/log-fixtures`
(membership logs, generated by `server/internal/grouplog`'s `TestGenerateFixtures`) tie the crypto and the log rules
of both sides together. Never edit these files by hand; regenerate them with their generator. The HTTP and WebSocket
API is tied by running the app's e2e suite against the real server (`app/e2e/against-server.sh`, part of `make test`). A protocol change updates
`protocol/docs`, the data and both sides in one change, and `make test` (both suites) must pass.

## Releases

Tags are prefixed per side: `app-vX.Y.Z` builds the installers, `server-vX.Y.Z` builds the Docker image. Only the root Makefile makes them: `make bump-app` bumps the app's version, commits and tags it, `make bump-server` tags the server's next version; both run `make test` first and push if it passes. CI runs
only the side whose paths changed; a change under `protocol/` runs both, and a server change also runs the app's CI,
which ends with its e2e suite against the real server.
