# Membership log fixtures

Valid and invalid membership logs (E2EE §4). They are the contract between the server's validator and any client's: both replay every file and must accept and reject exactly the same ones.

Each file is one log:

| Field | |
|---|---|
| `name` | The file name without `.json` |
| `valid` | Whether the **last** entry must be accepted. Every entry before it is setup and is always valid |
| `entries` | The log in order, each `{raw, sig}` |

`raw` is the exact signed bytes of an entry and `sig` its Ed25519 signature. Both are **standard padded base64** here, unlike the entry contents themselves, which use base64url without padding (§4.1). An invalid last entry fails either when parsed (bad signature, non-canonical encoding) or against rules 1–12.

**These files are the source of truth.** A client that keeps its own copy must keep it identical to these.

- **Generated by** `GENERATE_FIXTURES=1 go test ./internal/grouplog/`.
- **Checked by** `go test ./internal/grouplog/`. CI runs it.

Crypto constructions other than log entries are in `../vectors`.
